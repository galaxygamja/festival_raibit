# 드래곤 펀치 2인 대결 스코어보드 — 구현 요청

이 폴더의 `Main.dc.html`(관중용 스코어보드)과 `Admin.dc.html`(관리자 화면)이 확정된 디자인이다.
이 두 파일은 디자인 도구 전용 형식(`<x-dc>`, `{{}}` 템플릿, `sc-for`/`sc-if`)이라 그대로 실행되지 않는다.
**레이아웃, 색, 글꼴, 7세그먼트 도형 계산(`digits()` 함수), 레벨 미터, 왕관 SVG를 그대로 옮겨서** 일반 HTML/CSS/JS로 다시 구현해라. 디자인을 임의로 바꾸지 마라.

## 1. 실행 환경

- **Windows와 macOS 둘 다**에서 돌아가야 한다. Electron + `serialport` 패키지로 만들고, `electron-builder`로 Windows용 `.exe`(portable 또는 설치형)와 macOS용 `.dmg`를 빌드하는 스크립트를 넣어라.
- 행사장에 인터넷이 없을 수 있다. **Do Hyeon 글꼴 파일을 앱에 포함**하고, 외부 CDN을 쓰지 마라.
- 화면은 1440×900 기준으로 디자인됐다. 어떤 해상도의 노트북이든 **비율을 유지한 채 꽉 차게 확대, 축소**한다(남는 부분은 배경색). 앱은 전체화면(kiosk)으로 시작한다.

## 2. 아두이노 입력 (아두이노 2대, USB 시리얼, 9600 baud, 줄 단위 `\n`)

아두이노 쪽 코드는 내가 아래 형식에 맞춰 직접 작성한다. 앱은 이 형식만 처리하면 된다.

| 보내는 쪽 | 줄 형식 | 의미 |
|---|---|---|
| P1 아두이노 | `P1 <정수>` | 직전 0.1초 동안의 센서 피크값. 0.1초마다 계속 보냄 |
| P2 아두이노 | `P2 <정수>` | 위와 같음 |
| START 버튼이 달린 아두이노 (둘 중 한 대) | `START` | 물리 START 버튼이 눌림 |

- 연결된 시리얼 포트를 **전부 자동으로 열고**, 줄 앞부분(`P1`/`P2`/`START`)으로 구분해라. 사용자가 포트 이름을 고르게 하지 마라(Windows `COM3`, macOS `/dev/cu.usbmodem…` 차이를 신경 쓰지 않게).
- 케이블이 빠졌다가 다시 꽂히면 자동으로 재연결해라. 최근 2초 동안 P1/P2 줄이 들어왔는지를 기준으로 관리자 화면에 연결 상태를 표시한다.
- 형식에 안 맞는 줄은 무시한다.

## 3. 점수 계산

- 원시 피크값 → 점수: `점수 = round(원시값 × 보정계수)`, 0~9999로 자른다.
- **보정계수는 P1, P2 각각 따로** 설정 파일에 둔다(기본값 1.0). 센서마다 감도가 다르기 때문이다. 나중에 내가 조정한다.

## 4. 경기 흐름 (상태 기계)

```
IDLE(대기) --START--> MEASURING(측정) --양쪽 50개 수신--> JUDGING(판정 5초) --> RESULT(P1 승 / P2 승 / DRAW)
RESULT --START--> MEASURING
```

- **IDLE**: 배너에 "START 버튼을 누르세요". 직전 경기 점수는 그대로 둬도 된다.
- **START 입력**: 물리 버튼의 `START` 줄 또는 관리자 화면의 "새 경기 시작" 버튼. 양쪽 점수를 0으로 비우고 MEASURING으로 간다. MEASURING, JUDGING 중에 들어온 START는 무시한다.
- **MEASURING**: START 이후 들어오는 P1 줄과 P2 줄을 **각각 50개씩** 모은다(0.1초 × 50 = 약 5초). 각 패널에 "측정 n / 50" 진행 막대를 보여주고, 지금까지의 최댓값을 점수로 실시간 표시한다. 양쪽 모두 50개가 차면 각자 50개 중 최댓값이 최종 점수다.
  - 안전장치: START 후 8초가 지나도 50개가 안 찬 쪽은 받은 것까지의 최댓값으로 확정한다(케이블 문제로 화면이 멈추지 않게).
- **JUDGING**: 5초 카운트다운(7세그먼트 숫자 5→1). 이 5초는 설정 파일 값으로 둬서 나중에 내가 3초로 바꿀 수 있게 해라.
- **RESULT**: 점수가 높은 쪽이 승자. 같으면 DRAW(배너 노란색 "DRAW" + "관리자가 새 경기를 시작하면 다시 측정합니다"). 승자 패널은 빛나고 패자 패널은 흐려진다(디자인 참고).
- 레벨 미터(1~15칸)는 `round(점수 / 9999 × 15)`칸이 켜진다.

## 5. 명예의 전당 (상위 5개)

- RESULT로 넘어가는 순간 **두 선수의 점수를 각각** 검사한다. **패자라도** 현재 5위보다 높으면(또는 기록이 5개 미만이면) 들어간다. DRAW도 같다.
- 새로 들어간 기록의 이름은 임시로 `ㅇㅇㅇ`이고, 어느 선수(PLAYER 1/2)가 세웠는지와 날짜, 시간을 함께 저장한다.
- 점수가 같으면 먼저 세운 기록이 위에 있다.
- 순위 표시: 1, 2, 3위는 금, 은, 동 왕관, 4, 5위는 숫자. 1위로 갈수록 점수 색이 진하다(디자인 그대로).

## 6. 저장 (로컬, 자동)

- 명예의 전당과 설정(보정계수, 판정 대기 시간)은 Electron `app.getPath('userData')` 아래 JSON 파일에 저장한다.
- **점수는 RESULT 확정 즉시 자동 저장**한다. 관리자는 이름만 고친다.
- 파일을 쓸 때는 임시 파일에 쓴 뒤 이름을 바꾸는 방식으로 해서, 저장 도중 꺼져도 파일이 깨지지 않게 해라.

## 7. 관리자 화면 (`Admin.dc.html` 디자인)

- 여는 단축키는 네가 정해라. 관중이 실수로 누를 일 없는 조합이어야 하고, 관리자 화면 상단에 단축키를 표시해라. `Esc`나 "스코어보드로 돌아가기"로 닫는다.
- 기능:
  - 명예의 전당 5개 줄의 이름 수정과 "이름 저장". `ㅇㅇㅇ`인 줄은 강조하고 개수를 표시한다.
  - "새 경기 시작": START와 동일하게 동작한다.
  - "경기 중지, 기록하지 않음": MEASURING, JUDGING 중이면 아무것도 저장하지 않고 IDLE로 돌아간다.
  - 아두이노 P1/P2 연결 상태 표시와 "포트 다시 연결".
  - 보정계수 P1/P2, 판정 대기 시간(초) 입력 칸. 디자인에는 없으니 같은 스타일로 연결 상태 카드 아래에 작게 추가해라.

## 8. 아두이노 없이 테스트하기 (필수)

개발용 시뮬레이션 모드를 넣어라(실행 인자 `--sim` 또는 관리자 화면 토글). 켜면:
- `S` 키 = START
- 0.1초마다 P1, P2에 가짜 피크값을 보내되, `A` / `L` 키를 누르는 동안에는 각각 큰 값이 들어온다(펀치 흉내).
- 동점 테스트용으로 두 쪽에 같은 값을 넣는 키 하나.

## 9. 완료 기준

- `npm start`로 실행되고, `--sim`으로 한 경기 전체(IDLE → MEASURING → JUDGING → RESULT)가 돌아간다.
- 명예의 전당 갱신(패자 포함), DRAW, 경기 중지, 이름 수정 후 앱 재시작해도 유지되는 것까지 확인한다.
- README에 실행 방법, 빌드 방법, 아두이노 줄 형식, 설정 파일 위치(Windows/macOS 각각)를 적어라.
