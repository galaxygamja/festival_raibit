## Commands

```bash
npm install
npm start                    # real hardware, fullscreen (last chosen mode is remembered)
npm run sim                  # no hardware: electron . --sim
npx electron . --sim --windowed   # windowed; --fullscreen forces fullscreen
npm test                     # node test/game.test.js (plain node, no framework)
npm run build:win            # portable + nsis (x64) -> dist/
npm run build:mac            # dmg, arm64 + x64 -> dist/ (both builds can run on macOS)
npx electron-builder --mac dir --arm64   # fast unpacked build -> dist/mac-arm64/raibitScoreboard.app
```

To run a dev copy without touching the real data or colliding with an installed copy (single-instance lock is per userData dir), pass a scratch data dir: `npx electron . --sim --windowed --user-data-dir=<tmp>`. Otherwise sim results are written into the real `~/Library/Application Support/raibitScoreboard`. Add `--remote-debugging-port=<port>` to drive the window over the Chrome DevTools Protocol for screenshots and scripted checks (get the page's `webSocketDebuggerUrl` from `http://localhost:<port>/json`; Node 22's built-in `WebSocket` is enough, the `ws` package is not installed). `window.api` is callable from `Runtime.evaluate`, e.g. `api.simKey('s', true)` or `api.setName('홍길동', true)`. `Control+D` / `Control+F` must be sent as key events with `code: 'KeyD'` / `'KeyF'`, and Korean text goes into the name box with `Input.insertText`. With `askName` on (the default), `api.simKey('s')` only opens the name prompt; use `api.setName(name, true)` or `api.start()` to actually start.

Installing on the user's Mac ("최신 버전 설치"): build with the fast dir command above, make sure `/Applications/raibitScoreboard.app` is not running, replace it with `dist/mac-arm64/raibitScoreboard.app`, then `xattr -cr` it (unsigned build). Check `CFBundleShortVersionString` afterwards.

There is no lint step and no way to run a single test. `test/game.test.js` is one script that runs every case, and new tests go in it too. Sim keys: `S` (start), `A` (hold to squeeze).

## Product rules (decided with the user; not obvious from code)

- **Hardware**: EMG sensor → **SpikerBox** → laptop over USB (binary waveform). A **separate Arduino** carries only the START button (`START` line at 9600 baud, plus an `ALIVE` heartbeat every 1 s). Reading EMG directly on the Arduino was abandoned because its raw values saturated at 1/1023.
- **One player**, punch-machine style: no opponent, no winner/draw. The goal is setting a record.
- One measurement = 5 seconds from the START signal: 50 samples at 0.1 s each. There is **no judging phase**. The result appears as soon as 50 samples are in (or after the 8 s timeout).
- **One sample** = the SpikerBox signal filtered by `EmgFilter` (80 Hz high-pass ×2 + notches at the mains frequency's odd harmonics, designed at the device's MSF rate; mains 60/50 Hz, notch on/off and high-pass Hz are settings), then the RMS over a 100 ms window (time-based, window mean subtracted), minus the resting RMS (영점, measured on the filtered signal) minus `emg.margin` (default 1.5), then scored by `settings.score = {ref, top, curve, points}` (2.1.10): strength is turned into **% of the reference force** `ref` (the operator's max squeeze, measured by 자동 보정 or "최대 힘 재기"), and `points` = `[[pct, score], …]` maps that piecewise linearly ((0,0) to the first point, flat after the last, clamped 0–9999; `scoreFromTable`). `curve`/`top` only generate `points` from a preset (`curvePoints`: score = top × (pct/100)^curve, presets 직선 1 / 완만 0.8 / 보통 0.6 / 가파름 0.45); dragging or editing a point sets `curve: null`. The user found the 2.1.8 `[strength, score]` table unintuitive; with % of `ref`, a new laptop/sensor only needs `ref` re-measured and the curve carries over. Default: ref 31, top 7000, curve 0.6 (same shape as the 2.1.7/2.1.8 defaults). `toScore` remains only for migrating 2.1.7 settings. The filter was chosen from the user's recordings (rest RMS 15 → 2, max ÷ rest 5× → 24×); the margin keeps rest at 0 points. FFT is not used.
- Final score = the **maximum** of the 50 samples, not the last or the average. During measurement the big number shows the **current** force, smoothly animated. The max appears in the small `측정 n / 50 · 최고` line.
- Every non-zero result is kept in `records.json` as `{id, name, score, at}`; the hall of fame is derived as the top 5 (score desc, earlier record wins ties), and the result screen shows the overall place (`place`/`total`). 0 points are never recorded. New entries are named `ㅇㅇㅇ`. In the admin screen the operator can view all records ("전체 기록 보기"), edit any name **and score**, delete single records (✕), or "기록 전체 삭제" (backs up as `records.json.bak-<time>`, returns the game to IDLE).
- **Main screen layout** (accepted by the user; PLAN.md §5.1 describes an earlier idea): two 15-step level gauges on the left and right edges, and between them the banner (state label, 7-segment score, progress or `전체 n위 / N개 기록 중`) stacked above the hall of fame. No P1/P2 panels.
- Admin screen shortcut is `Ctrl+D` on Windows and `Control+D` on macOS (not Cmd), and F11 toggles fullscreen. Keys are matched by `e.code` so they work with a Korean IME active.
- Bump the `package.json` version on every user-visible change (the user checks for this; both admin pages show it bottom-right from `app.getVersion()`). Changes since 2.1.0 are patch bumps (2.1.x); run `npm install --package-lock-only` so the lock file follows.
- **자동 보정** (page 3, asked for so the app works on any laptop/location with manual override kept): `calib.js`. Modes: `full` = rest 5 s → prep 2.5 s → max squeeze 4 s; `noise` = rest only (mains, rest RMS, margin); `max` = prep → squeeze (only `score.ref`, the former pending "최대 힘 보정" button). It collects all channels' raw frames (`serial` emits them as the 3rd `emg` arg), cuts windows on main's 100 ms tick, and `analyzeCalibration` picks mains 50/60 by lower filtered rest RMS, channel + high-pass (30/50/80/120 Hz) by best squeeze-top-quarter ÷ rest p95 (keeping the current value unless another is ≥10 % better, and keeping channel/HP if the ratio < 2.5 with a warning), rest = rest median, margin = (p95 − median) × 1.5 + 0.5 (min 0.5), max strength = top squeeze window. Nothing changes until the operator presses 적용 in the result dialog (full mode: checkbox to also set `ref`). START is ignored while it runs. Checked on the user's 2.1.6 recording: picks 60 Hz, rest ≈ 2, margin ≈ 1.2.
- **Challenger names** (`settings.askName`, toggle "이름 받고 시작" on admin page 1 and 3, default on): `Control+F` (Ctrl+F on Windows; macOS Control+Cmd+F stays fullscreen) opens a name box on the audience screen to set the next name ahead of time. With askName on, a START (Arduino or sim `S`) without a name does not start; main sets `name.prompt` and the box appears, Enter starts immediately (empty Enter starts as ㅇㅇㅇ), Esc cancels. The admin "측정 시작" button always starts. The name is stored with the record. Fireworks + "OOO님 N위 축하드립니다!" appear only when askName is on and the result made the hall of fame (top 5); the user explicitly asked that fireworks only run with names on.
- The user communicates in Korean; keep UI text and replies in Korean.

## Architecture

Electron app, two processes, no bundler. UI is fixed at 1440×900 design pixels and scaled to the window by `fit()` in `src/renderer/app.js`.

- **Main process** (`src/main/`) owns all state and timing. `main.js` wires everything. It ticks the game every 50 ms and pushes a single `payload` (`game, hall, ports, settings, sim, platform, fullscreen, ...`) to the renderer only when it changed. The renderer holds no authoritative state.
- `serial.js` opens every USB serial port, rescans every 2 s, and skips non-USB ports (Bluetooth etc.). It never routes by port name.
  - Each new port is first probed as a SpikerBox: 222222 then 500000 baud, sending `b:;` and looking for an `HWT` message or ≥20 frames with ≥90% channel-vote confidence. If both fail, the port opens as a 9600 text port (`START`, `ALIVE`). Port roles can also be fixed by hand in the admin screen (`settings.portRoles`), keyed by `usb:<vid>:<pid>:<serial>` when the port has a USB serial number (so a COM number change keeps the role) and by path otherwise.
- `hid.js` is the USB **HID** transport for SpikerBox Pro (vendor `0x2E73`, HWT `MUSCLESB`, 10-bit values around 512, 2 channels, 10 kHz; verified on real hardware over USB-C, no serial port appears). Since 2.1.8 its acquisition follows the user's `emg.py` (the script that reads the device correctly), so keep it equivalent to that file.
  - Reports are 64 bytes `[0x3F, len, payload…]` (Windows may prefix report ID 0). Commands are `[0x3F,0x3E,text,0-pad]`: `start:; board:;` on open (as in emg.py), then `?:; max:;` only to get `HWT`/`MSF` for the admin screen (emg.py does not send them; on the real device they changed neither the frame rate nor the decoded values), `h:;` on close. `node-hid` is in `asarUnpack`.
  - The payload goes to `HidDecoder`, not `SpikerBoxParser`: channel count from `BRD` (default 2, no vote), a frame is accepted only when the next start byte arrives, it has exactly 2×channels bytes and all values ≤ 1023; device messages up to 1024 bytes; an invalid report resets the decoder (`onBadReport`). A 500-case random differential test against emg.py's `Decoder` (corrupt bytes, >1023 values, long messages, BRD changes, bad reports) matched exactly; the old `SpikerBoxParser` path matched in 1/500. On clean streams and on whole-report drops both paths give the same values. Real device on Windows (2026-10-20, three captures of 8–20 s plus a live app run): ≈10,050–10,140 frames/s (the full 10 kHz, unlike the ≈8450 seen earlier on the Mac), new decoder output identical to emg.py frame for frame; the old parser dropped the first 30 frames and made one spliced frame when a device message landed mid-frame. On the same data the app's scoring RMS tracks emg.py's display RMS (correlation 0.99) at about 45–50 % of its size, because `emg.js` removes < 80 Hz and the mains harmonics. Without an `MSF` message the filter rate is 10 kHz for 2 channels, 5 kHz for 3–4 (as in emg.py). The scoring filter in `emg.js` is unchanged; emg.py's own display filter (60 Hz notch → 2500 Hz LP → 1 Hz HP) is not used.
  - `pickDevices` accepts any product ID and keeps one entry per device (vendor usagePage `0xFF00` preferred, deduped by `deviceKey` = vid:pid:serial). `serial.js` scans HID in the same 2 s loop and keys entries as `hid:<path>`.
  - Each scan closes HID entries whose path vanished (replug into another USB port), resends `start:;` after 2 s without frames and reopens after 3 s more, and backs off failed opens 2→4→8→10 s, surfacing `ports.openError` in the admin screen (usually Spike Recorder holding the device).
  - `SerialManager` takes `hidApi`/`listSerial`/`now`, so tests drive it with a fake HID and a fake clock (`scanHid(now)`).
- `spikerbox.js` parses the SpikerBox stream. A frame-start byte has bit 0x80 set, and the value is `((b0&0x7F)<<7)|(b1&0x7F)` per channel. Messages sit between escape markers `FF FF 01 01 80 FF` … `FF FF 01 01 81 FF` as `type:value;`. `emg.js` turns samples into the 100 ms score. Both are pure and testable, and PLAN.md §1–2 has the details.
- `game.js` is a pure state machine (IDLE → MEASURING → RESULT) that takes `now` as an argument so tests can drive the clock. Each sample goes through `scoreOf(strength, settings)` (% of `score.ref` → `score.points`) and the player keeps `rawMax` (max strength) for tuning. Every START source (Arduino, sim `S`, name box) goes through `requestStart()` in `main.js`, which applies the name gate; the admin button calls it with `fromAdmin`.
- `sim.js` replaces the hardware: it emits a fake SpikerBox byte stream, so it exercises the real parser, filter and RMS path. It mimics the real SpikerBox Pro recording: 10-bit (center 512), 60 Hz hum (raw rest RMS ≈ 14, filtered ≈ 2), wide-band noise for the muscle signal with a random filtered RMS of 15–45 per `A` press, so scores land around 4000–7000 at the default settings.
- `hall.js` holds the pure record/ranking rules (`addResult`, `hallOf`, `editRecords`, `deleteRecords`, `migrateRecords`). `store.js` persists `settings.json` and `records.json` in `userData`: write temp → fsync → rename, retry on Windows EPERM/EBUSY, and move unreadable files to `*.corrupt-<time>`. `normalizeSettings` migrates the v1 `calibration: {p1, p2}`. When `records.json` is missing, `main.js` migrates the v2.0.x `hall-of-fame.json` + `score-history.json` once (old files are left in place), and `normalizeRecords` drops the v1 `player` field.
- Admin has three pages: page 1 (records, game control, name toggle, zero), page 2 "진단" (below), and page 3 "설정" (`#settings`: score editor — ref/top inputs, curve presets, a graph in % of ref with draggable points and markers for the current strength and the last measurement's max `game.p1.rawMax`, examples, an optional point table; 자동 보정 card + modal `#cal-modal`; manual signal inputs; name toggle; settings export/import as JSON via `settings:export`/`settings:import`, which carry `score`, `askName`, `emg` but keep the local rest RMS and port roles, and accept 2.1.8 exports with `scoreTable`) Page 2 "진단" (`#diag`: raw waveform, 100 ms RMS history, signal numbers, per-port/HID details, recent logs). `diag.js` keeps a 20000-sample ring of the selected channel; `payload.diag` (from `diagPayload()`, which also includes `serial.diagnostics()` and a console ring buffer) is only sent while page 2 is open (`diag:set`). Page 2 also has a recorder (`recorder.js`): per 100 ms window one CSV row (`t_ms,label,rms,rms_raw,strength,rest_rms,score,mean,min,max,n,raw_start,phase`, `rms` is filtered, meta lines carry `emg` and `score`, `#` meta lines on top) in `userData/recordings/rec-<time>.csv`, plus the selected channel's raw samples as int16 LE in the matching `.raw` (`raw_start` indexes into it, so filters can be re-run offline). Number keys 0–4 set the label (none/쉼/약하게/중간/최대). The user records with it and hands the files over for analysis.
- The full record list is not in the pushed payload (it can be large). The payload carries `hall` (top 5), `recordsRev`, and `recordsTotal`; the admin screen calls `records:get` when `recordsRev` changes.
- **Renderer** (`src/renderer/`) is plain HTML/JS under a strict CSP (`self` only). It talks to main only through `window.api` defined in `src/preload.js` (contextIsolation + sandbox). Adding a feature that needs main usually means three edits: an IPC handler in `main.js`, a method in `preload.js`, and a call in `app.js`.
- A `requestAnimationFrame` loop in `app.js` exponentially smooths displayed numbers (`SMOOTH_MS`). The 7-segment digits come from `segments.js`.
- `arduino/start_button/start_button.ino` is the START button sketch (INPUT_PULLUP, debounced, `START` on press, `ALIVE` every 1 s).

## Build notes

- `serialport` ships N-API prebuilds, so `npmRebuild: false` is set in the electron-builder config (rebuilding fails on machines without node-gyp/distutils). `@serialport/bindings-cpp` must stay in `asarUnpack`.
- Only one app instance runs (single-instance lock) so two copies never fight over serial ports.
- Do Hyeon font is bundled in `src/renderer/fonts/` (OFL); the app must work offline.

## Gotchas

- The renderer rebuilds admin rows whenever the records change. `renderAdminRows` preserves what the user is typing (per record id and field), so keep that when changing it.
- The banner text is fixed at 980 px with `nowrap` because it previously wrapped the last Korean character onto a second line.
- `design/` and `design/claude-code-prompt.md` are the **initial** spec. The behavior above (immediate result, max score, Ctrl+D, app name, and v2's single player and SpikerBox) supersedes them. PLAN.md is the v2 migration plan; where it differs from this file (screen layout, `hall-of-fame.json`/`score-history.json`, which `records.json` replaced in v2.1.0), this file wins.
- On macOS the fullscreen toggle uses `setSimpleFullScreen` (instant, no Spaces animation), because `setKiosk(true)` left the window at its windowed size while `isKiosk()` reported true. Windows still uses kiosk.
- Non-standard baud 222222 on macOS through node `serialport` is unverified (PLAN.md §9).
- Real SpikerBox Pro (HID, `MUSCLESB`, 10-bit, rest ≈ 512) findings from the user's recordings (2026-10-20): EMG is on ch0 (ch1 unconnected); no clipping (302–970); on the Mac only ≈ 8450 of 10000 frames/s arrive over HID, in contiguous chunks (on Windows the full ≈ 10,050 arrive, see `hid.js` above), so mains hum shows at 51 Hz if you assume 8450 Hz (design filters at the MSF rate, not the measured rate); unfiltered rest RMS wanders 5–50 with mains hum even with the charger unplugged; after the filter rest ≈ 2 and max squeezes ≈ 34–38 (one 58). To re-check scoring offline, replay a recording's `.raw` through `EmgFilter` + `strengthOf` + `scoreOf` using the CSV's `raw_start`/`n` windows.
- Settings migrations live in `normalizeSettings`: no `emg.filtered` (≤ 2.1.6) → rest RMS dropped; no `score` → from the 2.1.8 `scoreTable` (`scoreFromLegacyTable`: ref = strength at 7000 points, default table → default score) or, ≤ 2.1.7, from `calibration`/`scoreCurve` via a table first. The saved file is only rewritten on the next save.
- `scoreFromTable` and `curvePoints` exist twice (`game.js` and the page 3 preview in `app.js`); change both together.
- Inside `#settings` a `[hidden]` rule with `!important` is needed because many elements there set `display` inline.
- The name box (`#name-modal`) stops key propagation so typing doesn't trigger sim keys, and ignores Enter while the IME is composing (`isComposing` / keyCode 229).
- Not yet verified: replug/stall/backoff on a real device (fake-HID tests only), the START Arduino, the exe on real Windows, the macOS fullscreen toggle on the installed app (checked in a dev run only).
